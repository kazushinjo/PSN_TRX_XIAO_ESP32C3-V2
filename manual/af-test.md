# マイクアンプ → ADC の AF 信号確認（PC の USB オーディオを信号源にする）

PC の USB オーディオドングルから試験用の正弦波を出し、アッテネータで数 mV に下げてマイクコネクタ（J7）に入れます。
マイクアンプ（U5A）の出力と XIAO の ADC 入力（D2/A2）で、波形・レベル・位相を確認します。

## 1. アッテネータ（−40dB）

```
 ドングル                                        マイクコネクタ J7
 ヘッドホン出力
 (L 側)  ──[ C1 1µF ]──[ R1 10kΩ ]──┬──(−)[ C2 10µF ](+)──── 2番 MIC
                                    │
                                 R2 100Ω
                                    │
 (GND)   ───────────────────────────┴───────────────────────── 4番 GND
```

| 部品 | 値 | 役割 |
|---|---|---|
| R1 | 10kΩ | 分圧の上側。ドングルから見た負荷も約 10kΩ になり、出力に負担をかけない |
| R2 | 100Ω | 分圧の下側。出力側のインピーダンスが約 100Ω と低いので、本体側のバイアス（4.7kΩ）の影響をほとんど受けない |
| C1 | 1µF（フィルム、なければ電解） | ドングル出力の直流を止める保険。なくても動くことが多い |
| C2 | 10µF 電解（16V 以上） | **必須**。MIC 端子には本体から +5V → 1kΩ → 4.7kΩ のバイアスがかかっていて、開放時は約 5V になる。これを R2 に流さず、ドングル側にも入れないため。**＋側を J7 の 2 番（MIC）に向ける** |

- 減衰量は 100 ÷ (10k + 100) で約 1/100（−40dB）。ドングルの出力が 0.3V なら約 3mV、1V なら約 10mV になる
- 低い周波数の落ち始めは、C2 と 4.7kΩ で約 3Hz、C1 と 10kΩ で約 16Hz。音声帯域には影響しない
- もっと下げたいときは R2 を 10Ω にする（−60dB、1V で約 1mV）。抵抗を差し替えるかスイッチで切り替えると、2 段階で使える
- 線はシールド線にし、アッテネータは J7 のすぐそばに置く

## 2. レベルの合わせ方

1. ドングルの L 側だけを使う（R 側は使わない）。GND は 3.5mm プラグのスリーブ
2. PC でトーンを出す。WaveGene や Audacity の「トーン生成」などで 1kHz の正弦波を出す
3. PC の「音声の強調」やイコライザなどの効果はすべて切る
4. ドングルの出力（C1 の前）をテスターの AC レンジかオシロで測り、PC の音量で合わせる。アッテネータの後はその 1/100 になる
   - 安いテスターは 1kHz では正確でないことがある。測るときだけ 100〜400Hz に下げると確実
5. 目安は 2〜10mV。一般的なエレクトレットマイクは、1Pa（話し声を近くで出したくらい）で数 mV〜10mV 程度を出すので、実際のマイクに近い状態になる

## 3. 確認方法

確認はすべて送信状態で行う。出力にダミーロードをつなぎ、PTT（J7 の 3 番）を GND に落とす。ファームウェアがマイクを読むのは送信中だけ。

### 3.1 オシロで比べる（波形・位相）

| チャンネル | 当てるところ |
|---|---|
| CH1 | U5A の出力（1 番ピン） |
| CH2 | XIAO の D2/A2 ピン（GPIO4、AF_ADC） |

- どちらも AC 結合にし、トリガは CH1 にする
- 波形の形が同じで、ずれ（位相差）が小さいことを見る。間の C65・R52 と R73/R74 のバイアスによる、わずかな進みや遅れは正常
- DC 結合に切り替え、A2 の中心が約 1.65V にあり、振幅が 0〜2.5V（ADC の範囲）に収まっていることを見る
- 周波数を 300Hz・1kHz・2.7kHz と変え、振幅と位相が大きく変わらないことを見る（音声帯域の特性）

### 3.2 オシロがない場合（シリアルで確認）

送信中に信号を入れたまま、シリアルから `dsp` を打つ。

- 「入力ピーク」が信号を止めたときより十分大きい → マイクアンプから ADC まで信号が届いている
- 「クリップ」「ADC あふれ」が増えていない → 入れすぎていない

これで分かるのはレベルだけで、位相は分からない。`tone` コマンドはマイクの代わりに内部で正弦波を作るので、この確認には使えない。

## 4. 正常な電圧の目安（3mV 入力）

J7 の 2 番に 1kHz・3mVrms を入れたときの計算値（`kicad/sim/af.py` のマイク系に、1 章のアッテネータ（出力 100Ω・C2 10µF）をつないで ngspice で計算）。

| 測るところ | 実効値 | オシロでの p-p | 前の点からの利得 |
|---|---:|---:|---|
| J7 の 2 番（MIC） | 2.9mV | 約 8mV | — |
| U5A の＋入力（3 番） | 3.1〜3.2mV | 約 9mV | Q14〜L7 の LPF で約 1.05 倍（+0.4dB） |
| **U5A の出力（1 番）** | **65〜67mV** | **約 185mV** | **約 21 倍（+26.4dB、R51 20kΩ／R50 1kΩ）** |
| **A2（AF_ADC）** | **45〜46mV** | **約 130mV** | 約 0.69 倍（C65・R52 22kΩ と R73/R74 で分圧） |

- 全体では、マイク入力から U5A の出力まで約 22 倍（+27dB）、A2 まで約 15.5 倍（+23.8dB）
- 幅は L7 の直流抵抗（30〜90Ω）の違い。実機で ±10〜20% くらいずれても正常
- DC 結合で見ると、U5A の出力の中心は電源の約半分、A2 の中心は約 1.65V
- ADC の範囲は 0〜2.5V（中心 1.65V、上側の余裕 約 0.85V）。A2 が約 0.6Vrms を超えるとクリップする。入力で約 40mVrms までは大丈夫（その手前で U5A も頭打ちになり始める）

| 症状 | 疑うところ |
|---|---|
| U5A の出力が 3mV 程度しかない（利得が 1 倍） | R51（20kΩ）・R50（1kΩ）・C63 の付け忘れ・向き違い |
| U5A の出力が数倍しかない | C63（10µF）の容量抜け・向き違い |
| U5A の＋入力に信号がない | Q14、C58・C61 の向き、L7 の断線 |
| A2 だけ小さい | C65 の向き（＋が U5A 側）、R52 |

## 5. マイクをつないだときのレベル

### 5.1 エレクトレット（コンデンサ）マイク

感度 −42dBV/Pa の標準的な品で計算。1Pa（94dB SPL）で MIC 端子に約 15mVrms 出る（本体の 4.7kΩ 負荷のため、データシートの 2.2kΩ 負荷の値 7.9mV/Pa より大きい）。

| 話し方（マイクまでの距離） | 音圧 | MIC 端子 | U5A の出力 | A2 |
|---|---|---:|---:|---:|
| 普通の声・30cm | 約 65〜70dB SPL（0.04〜0.06Pa） | 0.5〜1mV | 11〜22mV | 8〜15mV |
| 普通の声・10cm | 約 75〜80dB SPL（0.1〜0.2Pa） | 1.5〜3mV | 33〜65mV | 23〜45mV |
| **普通の声・口元 5cm** | **約 85〜90dB SPL（0.35〜0.6Pa）** | **5〜9mV** | **0.11〜0.2V** | **80〜140mV** |
| 大きな声・口元 | 94dB SPL（1Pa） | 15mV | 0.33V | 0.23V |
| 叫び声・口元 | 約 104dB SPL（3Pa） | 約 44mV | 約 1V（頭打ちし始める） | ADC の上限付近 |

- 表は平均的なレベル。声のピークはこれより約 10dB（約 3 倍）大きい
- マイクの感度は品物によって −38〜−46dBV/Pa くらい違うので、±4dB（0.6〜1.6 倍）程度ずれる
- 1 章のアッテネータで入れる 3mV は「普通の声で 10cm」くらい。口元で話すのに近づけるなら 5〜10mV で試す

### 5.2 マイクの種類と U5A の利得

ADC の振り切れ（0dBFS）は ±2048 カウント（約 ±1.25V）。口元で普通の声、`mic 0` のとき：

| マイク | MIC 端子 | A2（実効値） | 声のピーク | 判断 |
|---|---:|---:|---:|---|
| エレクトレット | 5〜9mV | 80〜140mV | 約 −12dBFS | 今の利得（21 倍）で足りる。S/N 約 45〜50dB |
| ダイナミック | 0.5〜1mV | 8〜15mV | 約 −30dBFS | アナログの利得が約 10dB 足りない。S/N 25〜30dB |
| アンプ内蔵型（電源は J7 の 1 番の +5V） | 数十〜数百 mV | — | — | `mic` を下げる |

- ノイズは ESP32-C3 の ADC で決まる（音声帯域で 0.3〜0.5mV 相当。NJM2904 のノイズはずっと小さい）。`mic`（デジタル利得）で上げるとノイズも同じだけ上がるので、ダイナミック型では話していないときの「サー」音が残る
- **ダイナミック型を使う場合だけ** R51 を 20kΩ → 68kΩ にする（U5A の利得 21 倍 → 69 倍、+10dB。NJM2904 の帯域は約 8.7kHz あり音声帯域では落ちない。100 倍を超えると 2.7kHz 付近が下がり始めるので、それ以上は上げない）。この定数ではエレクトレット型は大きな声（約 1Pa）で U5A が頭打ちになるので、エレクトレット型なら 20kΩ のまま

## 6. 通常運用での利得の合わせ方（`mic`・`out`）

`mic` はシリアルで送る設定コマンドで、ADC の後のデジタル利得を dB で変える（−12〜+30dB、6dB で約 2 倍）。部品の交換や半固定抵抗の調整はいらない。

1. 本体の XIAO（USB-C）と PC をつなぎ、Arduino IDE のシリアルモニタを **115200bps・改行（LF）あり** で開く
2. `dsp` で今の設定を見る（1 行目の「マイク +0.0 dB」が今の利得）
3. 出力にダミーロードをつなぎ、ハンドマイクの PTT を押して普段どおり話しながら `dsp` を何回か打つ
4. `mic 3` のように 3dB くらいずつ変えて 3 をくり返す
5. 決まったら `w` で保存する（打たないと電源を切ったときに元に戻る）

初めに試す値：エレクトレット型 `mic 0`、ダイナミック型 `mic 15`〜`mic 20`、アンプ内蔵型 `mic -6`〜`mic -12`。

### 6.1 `dsp` の入力ピークで判断する（`mic 0` のまま）

黙ったまま `dsp` を打った「入力ピーク」がノイズ、話しながら打った値が声のピーク（`dsp` を打つたびに 0 に戻る）。

| 話したときの入力ピーク | 判断 |
|---|---|
| 5000 以上（−16dBFS 以上） | 今の利得で十分 |
| 1000〜5000 | `mic` で上げれば使える |
| 1000 未満 | マイクの出力が小さい（6.2 の 3 を確認）か、アナログの利得不足 |

黙ったときと話したときの比（20·log）が 30dB 未満なら、アナログの利得を上げる効果が大きい。

### 6.2 「送信で利得が足りない」と感じるとき（エレクトレット型）

エレクトレット型ならアナログの利得は足りているので、次の順に確かめる。

1. **`out`（出力レベル）が低い**：送信出力の大きさは `mic` ではなく `out` で決まる（初期値 10%）。電力計で見ながら `out 20` → `out 30` … と上げ、尖頭 1W 前後になる値にする。上げすぎると歪む
2. **ALC が強く効いている**：話している間、LCD の ALC の表示がずっと大きく出ているなら、ALC が利得を絞っているので `mic` を上げても出力は増えない。`mic` を下げるか、`out` で出力を合わせる
3. **マイク自体の出力が小さい**：入力ピークが 1000 未満なら、マイクの感度、口からの距離、配線（MIC が 2 番・GND が 4 番、ハンドマイク側の配線が本体のピン配置と合っているか）を確認する。送信中の MIC 端子の直流電圧が約 2〜4.5V あるかも見る（0V や 5V ちょうどなら配線かマイクの不良）
4. **それでも小さいとき**：`mic` で +6〜+10dB 上げる。エレクトレット型なら S/N に余裕があるので、デジタルで上げても問題ない。決まったら `w` で保存

受信機で自分の送信をモニターし、音が割れず小さすぎない値にするのが一番確実。

## 7. 補足

- **SSB では、マイクアンプ → ADC の位相はほとんど問題にならない。** I と Q の 90° の位相差は、ADC で読み込んだ後にファームウェアで作っている。マイクアンプから ADC までの位相のずれや極性の反転は I・Q の両方に同じように加わるので、逆側の側帯波の抑圧には影響しない。この区間で確認すべきなのは、信号の大きさ・歪み・帯域
- 側帯波の抑圧（I/Q の位相）は、[`送信IQ調整手順.md`](送信IQ調整手順.md) のとおり `tone 1000` と `iqd`・`iqa` で合わせる
- **グラウンドループ**：PC と本体（XIAO）を USB でつないだまま、ドングルも同じ PC に挿すと、GND がループになりハムが乗ることがある。気になるときは、片方を外すか、ノート PC をバッテリー駆動にする
